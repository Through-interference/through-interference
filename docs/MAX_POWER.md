# Максимальная мощность E22-900M30S: полный гайд

Инструкция рассчитана на две обычные ESP32 DevKit / ESP32-WROOM с 4 МБ Flash и E22-900M30S. Версия прошивки **2.0.1-CAN-E22**. Для ESP32-S3/C3 нужны другие сборки.

Объяснение устройства проекта и исправления находится в [POWER_FIX.md](POWER_FIX.md). Здесь перечислены конкретные действия. Прошивается ESP32, которая управляет радиомодулем; отдельную программу в E22 записывать не нужно.

Порядок действий: проверить антенны и питание, прошить землю и борт, на каждой плате задать `PWR 22`, сохранить и проверить после перезапуска. Земля получает сборку **tx**, борт **rx**. Обе платы передают и принимают радио.

**22 — максимальная настройка чипа SX1262 для работы E22-900M30S в области паспортных 30 dBm, около 1 Вт.** Фактическую мощность подтверждает измерение на выходе. Значение 30 в поле мощности вводить не нужно.

## 1. Проверь антенны, питание и провода

1. Выключи питание перед проверкой проводов.
2. Подключи к каждому E22 штатную антенну рабочего диапазона до включения передачи.
3. На каждый E22 подай стабильные **5 В** от источника с запасом по току, минимум **1 А на радиомодуль**. Для двух модулей от одного источника закладывай минимум 2 А на них, плюс потребление остального оборудования. Выход 3,3 В ESP32 для получения максимума E22 не подходит.
4. Соедини GND источника, E22 и ESP32. Не соединяй выходы двух разных источников 5 В. При подключении ESP32 по USB внешние 5 В можно подавать только на E22, объединив их GND.
5. На сигнальных контактах остаётся логика **3,3 В**. Внешние 5 В подаются только на VCC модуля, не на GPIO ESP32.
6. Для проверки на максимальной мощности разнеси антенны на несколько метров. Не ставь передатчик вплотную к приёмнику.

Настроенная наземная плата начинает передавать радиопакеты автоматически после загрузки. Если вместо антенны используешь измерительный тракт, подключи его при выключенном питании до включения платы.

Проверь провода по надписям на модуле и плате. Номера в таблице относятся к выводам E22; GPIO не являются порядковыми номерами контактов гребёнки DevKit.

| Контакт E22-900M30S | Подключение |
| --- | --- |
| VCC, выводы 9 и 10 | Питание 5 В |
| GND | Общая земля источника, модуля и ESP32 |
| SCK, вывод 18 | GPIO18 ESP32 |
| MISO, вывод 16 | GPIO19 |
| MOSI, вывод 17 | GPIO23 |
| NSS, вывод 19 | GPIO5 |
| NRST, вывод 15 | GPIO14 |
| BUSY, вывод 14 | GPIO26 |
| DIO1, вывод 13 | GPIO33 |
| RXEN, вывод 6 | GPIO32 |
| TXEN, вывод 7 | GPIO25 |

Распиновка одинаковая для земли и борта. В этой схеме TXEN управляется GPIO25; дополнительно соединять TXEN с DIO2 не нужно. Провода CAN для изменения мощности переставлять не нужно. На борту остаётся существующий CAN-трансивер с GPIO4 TX / GPIO17 RX; на земле физического CAN нет.

## 2. Скачай репозиторий с готовыми прошивками

Исправление и готовые прошивки сейчас находятся в ветке **codex/e22-max-power**. В GitHub открой [эту ветку репозитория](https://github.com/Through-interference/through-interference/tree/codex/e22-max-power), нажми **Code → Download ZIP** и распакуй архив целиком.

Если используешь git, скачай нужную ветку явно:

```text
git clone --branch codex/e22-max-power https://github.com/Through-interference/through-interference.git
cd through-interference
```

После включения исправления в main можно будет скачивать main. До этого обычный git clone без выбора ветки скачает прежнюю версию без готовых файлов.

В корне проекта должны находиться `README.md`, `platformio.ini`, `tools/` и папка `firmware/2.0.1-CAN-E22/`. Если папки firmware нет, выбрана версия проекта без этого исправления.

В `firmware/2.0.1-CAN-E22/ground/` лежат файлы земли, в `air/` файлы борта. Рядом находятся адреса записи в `manifest.json` и контрольные суммы `SHA256SUMS.txt`. Все необходимые файлы уже есть в репозитории; отдельный архив из переписки не нужен.

**Все команды ниже выполняются из корня проекта, где лежит README.md.** Открой там терминал или перейди туда командой `cd`. Собирать код для установки готовых файлов не требуется.

## 3. Установи программу прошивки

Нужен Python 3.10 или новее. Если его ещё нет, установи Python с python.org.

На Windows открой обычную командную строку **cmd**, не PowerShell:

```bat
py -3 -m venv .flash-venv
.flash-venv\Scripts\activate.bat
python -m pip install esptool==4.11.0 pyserial==3.5
```

На Linux / macOS:

```bash
python3 -m venv .flash-venv
source .flash-venv/bin/activate
python -m pip install esptool==4.11.0 pyserial==3.5
```

На Ubuntu при отсутствии venv сначала выполни `sudo apt install python3-venv`. Если нет доступа к USB-порту, выполни `sudo usermod -aG dialout "$USER"` и заново войди в систему. Python из созданного окружения запускай без sudo.

Все дальнейшие команды одинаковы на этих системах. При открытии нового терминала снова активируй `.flash-venv` командой для своей системы.

## 4. Определи USB-порты

Закрой GUI, монитор PlatformIO, Arduino Serial Monitor и другие программы порта. Выполни:

```text
python -m serial.tools.list_ports -v
```

Подключай ESP32 по одной и записывай появляющийся порт. Подпиши платы как землю и борт. Примеры имён: `COM7` на Windows, `/dev/ttyUSB0` на Linux, `/dev/cu.usbserial-10` на macOS. У тебя имена могут отличаться.

Во всех командах **замени GROUND_PORT на настоящий порт земли, AIR_PORT на настоящий порт борта**. Скобки вокруг имени порта не нужны. После переподключения порт может измениться. Для новых одинаковых ESP32 роль определяется выбранной сборкой.

## 5. Сохрани резервные копии

Для уже работающей пары сначала запиши текущие параметры каждой платы. Открой её порт командой ниже, подставив сначала GROUND_PORT, затем AIR_PORT:

```text
python -m serial.tools.miniterm GROUND_PORT 115200 --eol CRLF --echo --rts 0 --dtr 0
```

Введи `VER`, затем `CFG` с Enter после каждой команды и сохрани ответы в текстовый файл. Запиши частоты PRIM/BACK, PWR, MOD, SLOT и FHSS каждой платы. Для выхода нажми Ctrl+]. Это не меняет конфигурацию. Терминал перед прошивкой закрой.

Затем сохрани обе старые прошивки вместе с настройками. Это чтение, оно не меняет плату:

```text
python -m esptool --chip esp32 --port GROUND_PORT --baud 115200 read_flash 0x0 0x400000 backup-ground.bin
python -m esptool --chip esp32 --port AIR_PORT --baud 115200 read_flash 0x0 0x400000 backup-air.bin
```

Для платы с 4 МБ Flash размер каждого файла должен быть 4 194 304 байта. Копии содержат ключи пары, храни их у себя.

## 6. Прошей землю

Проверь, что выбран порт наземной ESP32. Выполни одной строкой:

```text
python -m esptool --chip esp32 --port GROUND_PORT --baud 115200 write_flash --flash_mode dio --flash_freq 40m --flash_size 4MB 0x1000 firmware/2.0.1-CAN-E22/ground/bootloader.bin 0x8000 firmware/2.0.1-CAN-E22/ground/partitions.bin 0xe000 firmware/2.0.1-CAN-E22/ground/boot_app0.bin 0x10000 firmware/2.0.1-CAN-E22/ground/firmware.bin
```

Дождись завершения всех четырёх записей, проверки данных и сообщения о перезапуске. Во время записи питание и USB не отключай.

Если команда долго пишет `Connecting...`, удерживай **BOOT**, нажми и отпусти **EN/RESET**, затем отпусти BOOT после начала записи. Если команда уже завершилась ошибкой, повтори её с этой последовательностью кнопок.

## 7. Прошей борт

Выбери порт бортовой ESP32 и файлы из `air`:

```text
python -m esptool --chip esp32 --port AIR_PORT --baud 115200 write_flash --flash_mode dio --flash_freq 40m --flash_size 4MB 0x1000 firmware/2.0.1-CAN-E22/air/bootloader.bin 0x8000 firmware/2.0.1-CAN-E22/air/partitions.bin 0xe000 firmware/2.0.1-CAN-E22/air/boot_app0.bin 0x10000 firmware/2.0.1-CAN-E22/air/firmware.bin
```

Файлы записываются отдельно. Эти команды не стирают область NVS `0x9000–0xDFFF`, где проект хранит настройки и ключ. Формат сохранённой конфигурации не меняется. **Не добавляй erase_flash или --erase-all при обновлении работающей пары.** Совместимость с прошивками, имеющими другую схему хранения, отдельно не проверялась; для них особенно нужна резервная копия.

## 8. Установи мощность 22 на обеих платах

### Уже работающая пара

Открой USB-терминал земли:

```text
python -m serial.tools.miniterm GROUND_PORT 115200 --eol CRLF --echo --rts 0 --dtr 0
```

Переключи клавиатуру на английскую раскладку. Вводи команды **по одной**, нажимая Enter и дожидаясь ответа после каждой:

```text
VER
CAN STAT
RST
CFG
```

`VER` должен сообщить `2.0.1-CAN-E22`. `CAN STAT` на земле должен содержать `ROLE=GROUND`, на борту `ROLE=AIR`. После `RST` дождись запуска: должны появиться `[AT][NVS] Configuration loaded successfully` и `+RADIO: READY`. Сверь ответ CFG с параметрами, записанными до прошивки.

**Если загрузка NVS завершилась ошибкой, появились size mismatch / validation failed / UNBOUND_USE_KEY_SAVE, прежние параметры изменились или READY не появился, остановись до SAVE.** Не выполняй RESTORE и не запускай создание нового ключа для работавшей пары. Сохрани резервные копии и сообщения ошибки. SAVE при загрузке значений по умолчанию может затереть прежнюю конфигурацию нулевым ключом.

Только после успешной проверки загрузки прежних настроек введи:

```text
PWR 22
SAVE
RST
```

На `PWR 22` и `SAVE` должен прийти `OK`. При ошибке SAVE сохранение настройки не подтверждено.

После RST терминал оставь открытым. При успешном запуске ожидаются:

```text
+RADIO: CONFIG CHIP_PWR=22,OCP_MA=140
+RADIO: READY
```

Первая строка показывает применённые настройки чипа, вторая успешный запуск радио. Это не измерение выходной мощности. Введи `CFG` ещё раз: в ответе должно быть `PWR=22`.

Выйди из терминала сочетанием **Ctrl+]**. Открой борт:

```text
python -m serial.tools.miniterm AIR_PORT 115200 --eol CRLF --echo --rts 0 --dtr 0
```

Повтори те же команды и проверки. Существующие частоты, модуляцию и ключи не меняй. Затем выключи и включи питание обеих плат и снова проверь `CFG`, чтобы убедиться в сохранении значения.

**GUI предназначена для земли и отклоняет бортовую плату.** На земле после проверки загрузки прежних настроек можно использовать GUI вместо терминала: в поле «TX чипа (dBm)» выбрать 22, нажать стрелку и SAVE. Для запуска обновлённой панели установи зависимости командой `python -m pip install -r requirements-console.txt`, затем выполни `python gcs_panel.py`. На Linux для GUI нужен пакет `python3-tk`; на других системах нужен Python с поддержкой Tk. Перед GUI закрой терминал. Для борта используй USB-терминал выше.

### Новая или сброшенная пара

Сначала проверь VER и роли обеих плат через терминал, затем закрой терминалы. Сообщение `ERROR: UNBOUND_USE_KEY_SAVE` означает, что радио не получило ненулевой ключ пары.

Для новой пары подключи обе ESP32 к одному компьютеру и выполни:

```text
python -m tools.provision --ground-port GROUND_PORT --air-port AIR_PORT --new-key --power 22
```

Утилита создаст общий случайный ключ, сохранит его на обеих платах, задаст GFSK250, 868,0/869,1 МГц, мощность чипа 22 и CAN борта 500000, перезапустит платы и проверит чтение настроек. Затем проверь CFG и сообщения запуска по процедуре выше. Утилита не измеряет RF-мощность и не подтверждает доставку CAN.

**--new-key заменяет ключи обеих плат. Для увеличения мощности уже работающей пары этот шаг не нужен.** При ошибке настройки пары устрани причину и повтори операцию для обеих плат.

## 9. Проверь результат

На обеих платах должны выполняться три условия:

1. VER сообщает `2.0.1-CAN-E22`, CAN STAT показывает правильную роль.
2. После запуска есть `CONFIG CHIP_PWR=22,OCP_MA=140` и `+RADIO: READY`.
3. CFG после полного выключения и включения содержит `PWR=22`.

Для проверки радио включи обе платы с одинаковыми частотами, модуляцией и ключом. В терминале земли дважды запроси `CAN STAT` с интервалом в несколько секунд. Проверь рост RF_TX/RF_RX и LINK=UP. Радиообмен начинается автоматически, CAN OPEN для него не требуется.

Для передачи полезных CAN-кадров через USB земли нужен сеанс `CAN OPEN`. В ручном терминале продлевай его повторной командой CAN OPEN чаще одного раза в 5 секунд; GUI и консоль делают это сами. Затем повтори тест передачи CAN в обоих направлениях. LINK=UP сам по себе не доказывает доставку CAN. Полная процедура находится в [README](../README.md) и [инструкции тестов](../tests/README.md); тесты с CANable выполняются на стенде.

Измерь напряжение на VCC/GND каждого E22 во время передачи. При просадках или перезапусках ESP32 сначала исправь питание.

Для проверки фактических 30 dBm нужен согласованный тракт 50 Ом с RF-измерителем, аттенюатором и кабелями, рассчитанными на мощность модуля и допустимый вход прибора. Подключай тракт при выключенной плате. Измеряется мощность **во время самого радиопакета**, с учётом всей полосы сигнала; к показанию добавляются потери аттенюатора и кабеля в dB. Прибор, усредняющий пакет вместе с паузами, покажет меньше и не позволит подтвердить 1 Вт во время передачи. Если такого оборудования нет, этот этап выполняется на радиотехническом стенде. RSSI второй платы измерение на выходе не заменяет.

## Если что-то не получилось

| Признак | Действие |
| --- | --- |
| Порт отсутствует | Проверь USB-кабель с передачей данных и драйвер USB-UART платы; повтори список портов. |
| Access denied / Permission denied / порт занят | Закрой остальные программы порта; на Linux проверь группу dialout. |
| Connecting... и тайм-аут | Повтори прошивку с BOOT/EN по шагу 6; проверь порт и питание ESP32. |
| Версия осталась старой | Проверь выбранную плату и порт; нажми EN/RESET и снова запроси VER. |
| Роль неправильная | Прошей правильным комплектом: ground для земли, air для борта. |
| UNBOUND_USE_KEY_SAVE | Для новой пары выполни первичную настройку обеих плат; для работавшей сначала проверь сохранение настроек и резервную копию. |
| PWR_RANGE_-9_TO_22 или RADIO_START=-13 | Задай PWR 22, не 30. Проверь VER. |
| RADIO_START=... без READY | Запиши код ошибки; проверь питание, SPI, BUSY, NRST и RXEN/TXEN. OK на PWR не подтверждает запуск радио. |
| RADIO_OCP_READBACK=... | Чтение OCP не подтвердило 140 мА, передача не запущена. Проверь питание и SPI; прошивка повторит инициализацию. |
| OCP_MA=140 отсутствует | Проверь VER и сообщения с момента перезапуска. Без ключа или при ошибке запуска CONFIG/READY не будет. |
| READY есть, связи нет | Проверь частоты, модуляцию, ключ, питание и антенны обеих плат. |
| Перезапуски при передаче | Проверь источник, длину и сечение проводов, напряжение на модуле и общую землю. |

## Что изменено и проверено

Прошивка выставляет OCP SX1262 в 140 мА после каждой успешной инициализации LoRa/GFSK, включая восстановление после сбоя, затем читает значение обратно из чипа. Ошибка настройки или несовпадение прочитанного значения останавливают запуск радио. Добавлены версия и сообщения конфигурации. Значение мощности по умолчанию остаётся 20; максимум выбирается командой PWR 22. Формат NVS и смысл PWR сохранены.

Сборки tx/rx подготовлены на основе актуального main проекта с исправлениями восстановления связи. Программные тесты проверяют четыре модуляции на обеих ролях, повторную инициализацию, ошибки настройки тока/запуска и потерянную запись OCP с несовпадением чтения. Обе сборки ESP32 собраны. Прошивка реальных плат, проверка питания и измерение RF-мощности при подготовке комплекта не выполнялись.

## Если хочешь собрать самостоятельно

Из корня репозитория с активированным Python-окружением:

```text
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -p "test_*.py" -v
python -m platformio run -e tx -e rx
python -m platformio run -e tx -t upload --upload-port GROUND_PORT
python -m platformio run -e rx -t upload --upload-port AIR_PORT
```

Для программных C++-тестов нужен компилятор C++; для записи готовых файлов он не нужен. Настройки после самостоятельной сборки выполняются по шагу 8.

## Почему используется именно такой способ прошивки

Это обычная запись программы в ESP32 через USB. Так же устанавливались прежние версии проекта: PlatformIO собирает исходники, а esptool записывает полученные файлы. Здесь этап сборки уже выполнен, чтобы другой человек мог прошить платы без установки всего набора средств разработки.

В команде перечислены четыре файла: загрузчик, таблица разделов памяти, служебные данные выбора приложения и само приложение. Их адреса соответствуют сборке esp32dev с 4 МБ Flash. Отдельная запись этих файлов сохраняет область NVS с настройками и ключом. Цельный образ с заполненными промежутками мог бы затронуть NVS, поэтому в этой инструкции используется запись отдельных файлов.

Прошивать нужно обе ESP32, поскольку каждая передаёт радио и обеим требуется исправленная настройка тока. Ввод PWR 22 в старой GUI меняет только настройку мощности; добавить отсутствующее поведение программы этим нельзя. После обновления ESP32 продолжает работать сама, без повторной прошивки при каждом включении.
