# CAN-телеметрия ESP32 + SX1262

Одна пара радиомодемов. Земля подключается к компьютеру по USB-UART. Борт подключается к Classical CAN через внешний трансивер SN65HVD230/VP230. Радиоканал переносит исходные CAN-кадры в обе стороны с сохранением ID, DLC, RTR и двоичных данных.

```
Компьютер ↔ USB-UART ↔ ESP32 tx ↔ SX1262 / радио ↔ ESP32 rx ↔ VP230 ↔ CAN БВС
```

Для стенда USB-CAN адаптер CANable заменяет CAN-узел БВС. Наземному ESP32 физический CAN-трансивер не нужен. Внешний антенный переключатель AS179-92LF не используется; RXEN/TXEN радиомодуля сохраняются.

## Запуск на этом компьютере

Открыть `start-panel.command`, выбрать наземный USB-порт и нажать «Подключить». Для текущего стенда земля: `/dev/cu.usbserial-10`, борт: `/dev/cu.usbserial-210`. Имена могут измениться после переподключения USB.

В панели доступны отправка CAN-кадра, просмотр полученных кадров, состояние радио и его локальные настройки. «Отправить CAN» означает постановку кадра в очередь. Выполнение команды подтверждается сообщением самого БВС, не локальным OK и не радио-ACK.

Для текущего стенда нажать «Подключить CANable», скорость 500000. Ввести ID и данные HEX. «Отправить CAN» отправляет с компьютера на CAN борта; результат виден в строке «На CAN борта принято». «Отправить с борта (CANable)» подаёт кадр в бортовой CAN; он приходит по радио в строку «Получен» на компьютере. Кнопки ничего не отправляют автоматически. При закрытии окна оба подключения закрываются.

Текстовые CMD:ARM/TAKEOFF и подобные команды не являются MAVLink и новой прошивкой отклоняются. Формирование команд автопилота выполняет наземное ПО с учётом его протокола.

## Обмен через терминал

Закрыть панель, чтобы освободить наземный serial-порт. Запустить:

```bash
/Users/timurkh/Desktop/BAS/through-interference/start-console.command --port /dev/cu.usbserial-10
```

В появившейся консоли:

```text
pc 00010203
bvs 04050607
stat
exit
```

`pc` отправляет с компьютера на CAN борта. `bvs` отправляет с CANable на компьютер. Строки `БОРТ ПОЛУЧИЛ` и `КОМПЬЮТЕР ПОЛУЧИЛ` формируются по фактическому приёму, не по постановке в очередь. Пример:

```text
БОРТ ПОЛУЧИЛ | ID=123 | DLC=4 | DATA=00010203
КОМПЬЮТЕР ПОЛУЧИЛ | ID=123 | DLC=4 | DATA=04050607
```

По умолчанию CAN ID=0x123, скорость 500000. Другой ID: `start-console.command --id 456`. Для реального CAN-узла БВС вместо CANable: `--no-canable`, команда `bvs` тогда недоступна. Автоматический тест двух диагностических сообщений: `start-console.command --port /dev/cu.usbserial-10 --demo`. Консоль не меняет прошивки или сохранённые профили.

## Проверка на двух компьютерах

Windows подключается к USB наземного ESP32, Mac с CANable подключается к CAN борта. На Windows запустить `start-ground.bat`, на Mac `start-air.command`. На обеих сторонах команда `send 00010203` отправляет данные на другой компьютер. Пошаговая схема и ожидаемые строки приёма: [TWO_COMPUTERS.md](docs/TWO_COMPUTERS.md).

## Развёртывание из чистого checkout

Нужен Python 3.10+ с Tk для панели, USB serial-драйвер для конкретной платы, PlatformIO. Для CANable на macOS нужен libusb.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
brew install libusb  # только macOS, для CANable
.venv/bin/pio run -e tx -e rx
.venv/bin/pio run -e tx -t upload --upload-port /dev/cu.usbserial-10
.venv/bin/pio run -e rx -t upload --upload-port /dev/cu.usbserial-210
.venv/bin/python gcs_panel.py
```

Зависимости зафиксированы: espressif32 6.9.0, Arduino ESP32 2.0.17 через эту платформу, RadioLib 7.1.2. `crypto_secrets.h` больше не требуется. Прошивки используют ранее сохранённую пару AES-ключей в NVS. Первая настройка новой пары описана в [протоколе](docs/CAN_PROTOCOL.md).

В этом рабочем каталоге инструменты уже установлены в `../.tools/can-venv`, а данные PlatformIO находятся в `../.tools/platformio`. Для сборки здесь:

```bash
PLATFORMIO_CORE_DIR=../.tools/platformio ../.tools/can-venv/bin/pio run -e tx -e rx
```

## Распиновка борта

| ESP32 | CAN-трансивер |
| --- | --- |
| GPIO4 / D4, выход TWAI TX | Вход TX/D трансивера |
| GPIO17 / D17, вход TWAI RX | Выход RX/R трансивера |
| 3.3V | VCC совместимого трансивера |
| GND | GND |

CAN-H/CAN-L соединяются с шиной БВС или CANable. Скорость по умолчанию 500000 бит/с. Нужны корректная терминация и общий опорный потенциал устройств. GPIO не подключаются непосредственно к CAN-H/CAN-L.

SPI радиомодуля: SCK18, MISO19, MOSI23, CS5; RST14, BUSY26, DIO1=33, RXEN32, TXEN25.

## Проверки

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
.venv/bin/python -m tools.can_client --port /dev/cu.usbserial-10 --seconds 30
.venv/bin/python -m tools.can_client --port /dev/cu.usbserial-10 --send t123200FF --seconds 5
```

Тест стенда отправляет диагностические кадры и двоичные фрагменты MAVLink HEARTBEAT. Запускать на отдельном стенде с CANable вместо настоящего автопилота:

```bash
.venv/bin/python -m tools.hardware_check \
  --ground-port /dev/cu.usbserial-10 --air-port /dev/cu.usbserial-210 \
  --modulation GFSK250 --burst 24 --output /tmp/can-results.json
```

Проверки отказов на отдельном стенде:

```bash
.venv/bin/python -m tools.recovery_check \
  --ground-port /dev/cu.usbserial-10 --air-port /dev/cu.usbserial-210 \
  --output /tmp/can-recovery.json
```

Этот тест временно меняет модуляцию борта без сохранения, заполняет очередь и перезапускает борт после диагностической передачи. Он не предназначен для подключённого автопилота.

Параметр `--modulation` применяет и сохраняет одинаковый профиль на обеих платах. Без этого параметра тест использует их текущие настройки. `--burst` проверяет одновременный поток в обе стороны и отсутствие дубликатов.

MAVLink v1/v2 определяется содержимым полезных данных. Радиомодем переносит двоичные CAN-кадры без разбора MAVLink. Тестовая нарезка MAVLink по 8 байт не объявляется универсальным протоколом MAVLink поверх CAN. Реальное подключение автопилота зависит от его CAN-протокола, например DroneCAN и поддерживаемого им туннеля.

## Активные модули

- `CanProtocol`: строгий кодек CAN/радиопакетов без Arduino, проверяется на компьютере.
- `ReliableEndpoint`: ограниченные очереди, подтверждения, подавление повторов и защита от переотправки команды в новую сессию после сброса адресата.
- `BridgeController`: общий цикл обеих прошивок, опрос с земли и ответ борта, USB.
- `CanHardware`: TWAI на борту, неблокирующая передача и восстановление bus-off.
- `crypto`: AES-128-GCM, идентификаторы партнёров и сохраняемые счётчики.
- `AtCommandManager`: локальная настройка модема, состояние и обработка длинных строк.
- `tools/can_client.py`: клиент USB с подтверждениями и защитой от повторной выдачи.

Файлы прежнего текстового протокола `TxOutbox`, `RxMessageStore`, `RxRadioRecovery` оставлены как история реализации и исключены из сборки. Время работы, скорость GFSK/LoRa и достигнутая полезная скорость различаются. LoRa SF9 существенно медленнее GFSK и ограничивает поток телеметрии.

Подробности формата и границ надёжности: [docs/CAN_PROTOCOL.md](docs/CAN_PROTOCOL.md).
