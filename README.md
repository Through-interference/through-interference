# CAN-телеметрия ESP32 + SX1262

Радиомост между UART наземной станции и CAN борта. Одна пара ESP32 + SX1262 передаёт Classical CAN-кадры в обе стороны с сохранением CAN ID, DLC, EXT/RTR и данных.

```text
GUI или консоль земли ↔ USB-UART ↔ ESP32 TX ↔ радио ↔ ESP32 RX ↔ CAN-трансивер ↔ CAN БВС
```

GUI общается с наземным модулем через UART. Бортовой модуль общается с БВС через CAN. В демонстрации CANable заменяет CAN-узел БВС. На Linux CANable использует штатный драйвер gs_usb и SocketCAN, поэтому доступен через обычные candump и cansend.

Поддерживается одна пара модемов. Внешний антенный переключатель AS179-92LF не используется. Линии RXEN/TXEN радиомодуля и AES-шифрование остаются.

## 1. Подключение

Нужны две прошитые ESP32 с SX1262, бортовой CAN-трансивер SN65HVD230/VP230, CANable с прошивкой gs_usb/candleLight, USB-кабели и питание обеих плат. CANable с последовательной прошивкой SLCAN требует другой настройки; описанный ниже сценарий рассчитан на gs_usb.

| ESP32 борта | CAN-трансивер |
| --- | --- |
| GPIO4 / D4, TWAI TX | Вход TX/D |
| GPIO17 / D17, TWAI RX | Выход RX/R |
| 3.3 V | VCC совместимого трансивера |
| GND | GND |

Соединить CAN-H ↔ CAN-H, CAN-L ↔ CAN-L и GND ↔ GND между CANable и трансивером. Скорость обоих CAN-узлов: **500000 бит/с**. На двух концах шины нужны терминаторы 120 Ом; встроенные резисторы/перемычки адаптеров тоже считаются. GPIO ESP32 не подключаются напрямую к CAN-H/CAN-L.

На наземной ESP32 CAN-трансивер не нужен. USB борта нужен для питания, прошивки и локальной диагностики; обычные данные борта идут через CAN.

SPI SX1262 на обеих платах: SCK18, MISO19, MOSI23, CS5, RST14, BUSY26, DIO1=33, RXEN32, TXEN25. Подключить антенны и питание радиомодулей.

## 2. Подготовка Linux

Основной сценарий рассчитан на Ubuntu/Debian с Python 3.10+, SocketCAN и драйвером gs_usb. В других дистрибутивах установить эквивалентные пакеты.

```bash
sudo apt update
sudo apt install git python3 python3-venv iproute2 can-utils
git clone https://github.com/Through-interference/through-interference.git
cd through-interference
```

На обоих компьютерах использовать одну версию проекта.

Все дальнейшие команды выполняются из этой папки. Можно копировать папку целиком на другой компьютер, но Python-окружение `.console-venv` переносить не нужно.

Для списка USB-UART портов:

```bash
./start-ground.sh --list-ports
```

Первый запуск создаёт `.console-venv` и устанавливает закреплённые зависимости из `requirements-console.txt`. Нужен интернет для их загрузки. Последующие запуски используют готовое окружение.

Наземный ESP32 определяется через CH340, VID:PID 1a86:7523. Если подключена одна такая плата, порт выбирается автоматически. Если подключены обе, укажи порт земли через `--port`. Номера `/dev/ttyUSB0` и `/dev/ttyUSB1` ниже являются примерами; сопоставь их с платами по выводу списка. Для постоянных имён можно использовать `/dev/serial/by-id/`.

При `Permission denied` проверить `ls -l /dev/ttyUSB0`. На Ubuntu/Debian обычно нужен доступ к группе dialout:

```bash
sudo usermod -aG dialout "$USER"
```

После изменения группы завершить сеанс и войти заново. Если группа устройства называется иначе, использовать её. Консоль и GUI запускать обычным пользователем.

## 3. CAN-интерфейс

После подключения CANable проверить имя интерфейса:

```bash
ip -br link
```

Обычно это can0. Если CAN-интерфейс не появился, проверить `lsusb`, подключение и наличие драйвера `gs_usb`; при необходимости `sudo modprobe gs_usb`. Интерфейс can0 не является USB-UART портом ESP32.

Один раз настроить интерфейс:

```bash
./setup-can.sh can0 500000
```

Эквивалентные команды:

```bash
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 500000 restart-ms 100
sudo ip link set can0 up
ip -details -statistics link show can0
```

В отдельном терминале прослушивать CAN:

```bash
candump -tz can0
```

В другом терминале отправить данные на бортовой ESP32:

```bash
cansend can0 123#00010203
```

Чтобы они дошли по радио до компьютера земли, там должна работать консоль ground или GUI с открытым UART-портом. Ожидаемый результат на земле:

```text
КОМПЬЮТЕР ПОЛУЧИЛ | ID=123 | DLC=4 | DATA=00010203
```

candump также показывает локально отправленные кадры. Одна строка в candump после cansend подтверждает локальный CAN-трафик; прохождение радио проверяется получением на земле.

## 4. Обмен на двух компьютерах

```text
Компьютер земли ↔ USB ↔ ESP32 TX ↔ радио ↔ ESP32 RX ↔ CAN-трансивер ↔ CANable ↔ компьютер борта
```

На компьютере земли подключить только наземный ESP32 и выполнить:

```bash
./start-ground.sh
```

Если нужен явный порт:

```bash
./start-ground.sh --port /dev/ttyUSB0
```

На компьютере со стороны борта подключить CANable, оставить питание бортового ESP32 и выполнить:

```bash
./start-air.sh --can-channel can0
```

Скрипт проверит скорость и состояние SocketCAN. Если нужна настройка интерфейса, он запросит sudo для команд ip; сама передача данных не требует sudo. Не использовать listen-only, loopback или CAN FD.

На земле в приглашении `can>`:

```text
send 00010203
```

На стороне CAN должно появиться:

```text
БОРТ ПОЛУЧИЛ | ID=123 | DLC=4 | DATA=00010203
```

В консоли стороны CAN отправить ответ:

```text
send 04050607
```

На земле должно появиться:

```text
КОМПЬЮТЕР ПОЛУЧИЛ | ID=123 | DLC=4 | DATA=04050607
```

На стороне CAN вместо start-air.sh можно использовать candump и cansend из предыдущего раздела. Эти инструменты не нужны на компьютере земли, если он работает только через USB-UART.

`stat` на земле показывает состояние радио и очередей. `stat` на стороне CAN сообщает о подключении адаптера. `exit` закрывает консоль. Вводить данные без кавычек, по две HEX-цифры на байт, максимум 8 байт за отправку. Идентификатор по умолчанию 0x123, другой задаётся параметром `--id 456`.

## 5. Обмен на одном компьютере

Подключить к нему CANable и USB земли. USB борта может быть подключён для питания. Явно выбрать порт земли:

```bash
./start-demo.sh --port /dev/ttyUSB0 --can-channel can0
```

В одной консоли доступны оба направления:

```text
pc 00010203
bvs 04050607
stat
exit
```

`pc` отправляет с UART земли через радио в CAN. `bvs` отправляет через CANable и борт обратно на UART земли. Строки ПОЛУЧИЛ формируются при фактическом приёме. Строка ОТПРАВИЛ подтверждает только локальную передачу/постановку в очередь.

Автоматический тест двух направлений:

```bash
./start-demo.sh --port /dev/ttyUSB0 --can-channel can0 --demo
```

Он отправляет два свежих диагностических пакета с уникальными данными и завершается с кодом 0 только после их фактического приёма на противоположных концах. При ошибке код завершения ненулевой. Нужны обе платы, CANable и исправная радиосвязь. Этот тест запускать на стенде без настоящего автопилота.

## 6. GUI через UART

```bash
sudo apt install python3-tk
./start-panel.sh
```

Выбрать USB-порт наземного ESP32 и нажать Подключить. Заполнить CAN ID `123` и данные `00010203`, нажать Отправить CAN. Проверить кадр через candump на стороне борта. Для ответа выполнить там `cansend can0 123#04050607`; полученные данные появятся в GUI.

UART работает на 115200 бод. Статус «Подключено» появляется после ответа наземного модема с `ROLE=GROUND,OPEN=1`. При выборе USB борта или отсутствии ответа панель закрывает порт и сообщает причину в журнале.

Закрыть ground/bench консоль перед открытием GUI: один процесс владеет USB-UART портом. Кнопка Подключить CANable в GUI нужна только для стенда на одном компьютере с локальным адаптером; SocketCAN перед этим настроить через setup-can.sh.

## 7. Прошивка и первая настройка новой пары

Для уже настроенной пары повторная прошивка и смена ключей не нужны.

Для сборки и прошивки из чистого проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/pio run -e tx -e rx
.venv/bin/pio run -e tx -t upload --upload-port /dev/ttyUSB0
.venv/bin/pio run -e rx -t upload --upload-port /dev/ttyUSB1
```

tx означает землю, rx означает борт. Порты подставить по фактическому подключению. PlatformIO и зависимости зафиксированы в platformio.ini/requirements-dev.txt.

Для новых или сброшенных плат подключить обе по USB к одному компьютеру, закрыть GUI/консоли и выполнить:

```bash
.venv/bin/python -m tools.provision \
  --ground-port /dev/ttyUSB0 --air-port /dev/ttyUSB1 --new-key
```

Инструмент проверяет роли плат, генерирует один новый случайный AES-ключ для обеих, сохраняет GFSK250, 868.0/869.1 МГц, CAN борта 500000, затем перезапускает платы и проверяет загрузку настроек. Ключ не печатается и не записывается в проект. `--new-key` заменяет ключи обеих плат; для обычной демонстрации это не нужно. Если операция прервалась, повторить её для обеих плат.

## 8. Диагностика

LINK=UP означает обмен радиопакетами, но не подтверждает передачу по CAN. Если кадр не дошёл, проверить питание, CAN-H/CAN-L/GND, скорость 500000, терминацию и состояние `ip -details -statistics link show can0`.

При ошибке возврата радио в приём прошивка повторно инициализирует модуль через 250 мс; ошибки самой инициализации повторяются с интервалом 2 секунды. После неудачного запуска драйвера CAN борт повторяет попытку каждые 2 секунды. В локальном `CAN STAT` поле `CAN_READY` показывает, запущен ли драйвер CAN; на земле оно всегда 0, поскольку физического CAN там нет.

`CAN STAT` показывает локальные счётчики. На земле нет физического CAN, поэтому CAN_FAIL=0 на земле не доказывает исправность CAN борта. Через USB борта доступны команды `CAN STAT` и `CAN DIAG` для чтения очередей, реальной скорости, GPIO и аппаратных ошибок. Это команды UART-сервиса платы, а не команды приглашения can>.

Формат UART-команд и радиопакетов: [CAN_PROTOCOL.md](docs/CAN_PROTOCOL.md).

Сборка тестов и аппаратные проверки: [tests/README.md](tests/README.md).
